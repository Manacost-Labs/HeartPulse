# Обновление данных после патча Полей сражений

## Источники и порядок проверки

1. Сверить состав патча с официальными примечаниями Blizzard.
2. Запустить `kolodahs-sync@cards.service` для существ и заклинаний.
3. Запустить `kolodahs-sync@libraries.service` для дополнительных библиотек.
4. Запустить `kolodahs-sync@heroes-refresh.service`, если добавлены герои.
5. Проверить публичные API `db.kolodahs.ru` и прокси `arena.hs-manacost.ru`.
6. Очистить прикладной кеш перезапуском `hs-arena.service`, только если публичный
   ответ продолжает содержать старую версию после успешного импорта.

## Темные дары сезона 14

Blizzard не предоставляет для Темных даров отдельный `bgCardType`. Импорт
обнаруживает их в HearthstoneJSON по стабильному префиксу
`BG36_MidGameEffect_000t` и типу `SPELL`. Ожидаемое число карточек для патча
36.2 — 43. Они доступны через `/api/v1/dark-gifts` и проксируются приложением
через `/api/bg/library/extra/dark_gift`.

Четыре пары даров имеют одинаковые русские и английские названия, но разные
`card_id`, DBF и эффекты. Поэтому каталог Темных даров дедуплицируется только
по `card_id` (с DBF как резервом), а не по локализованному названию. Контрольная
проверка страницы должна показывать `43 загружено` и находить карту как по
русскому, так и по английскому названию.

## Золотые версии новых существ

`sync_battlegrounds_images.py` всегда предпочитает локализованный `imageGold`
из Blizzard API. После выхода патча карточки HearthstoneJSON могут появиться
раньше, чем Blizzard начнет возвращать их изображения. Для существ, у которых
золотого изображения еще никогда не было, синхронизатор временно загружает
полный golden-рендер HearthPwn в `/uploads/golden/{card_id}.png` и публикует
локальный URL только после проверки PNG и атомарной записи файла.

Fallback не перезаписывает уже существующие локальные изображения. Когда
Blizzard начинает возвращать `imageGold`, изменившийся URL источника
автоматически заменяет временный рендер локализованной версией Blizzard.

## Временные исправления текста Constructed

Свежий балансный патч иногда появляется в примечаниях раньше, чем в API
Blizzard. `sync_constructed_cards.py` допускает узкие текстовые исправления,
которые применяются только при наличии маркера старого текста. После обновления
официального API такое исправление автоматически перестает влиять на запись.

Если Game Data API целиком пропустил новые коллекционные карты, нельзя
добавлять в формат весь каталог HearthstoneJSON: в нем остаются старые и
внутренние записи. Допустим только явный список ID, подтвержденный примечаниями
Blizzard, с датой окончания события. Для события «Zuramat's Rampage!» патча
36.2 это `JAIL_EVENT_100`, `JAIL_EVENT_101` и `JAIL_EVENT_102`, доступные с
4 по 25 августа 2026 года. Fallback выключается 26 августа или раньше для
каждой карты, которую начал отдавать Blizzard.

Проверка после импорта должна подтвердить для каждого ID русское и английское
название, текст, изображение и присутствие одновременно в Standard и Wild.

Карточные страницы должны строить same-origin URL изображения по каноническому
`card_id`, если он присутствует, и использовать DBF только для старых записей
без ID. Blizzard может не включать событийную карту в карточный каталог по DBF,
когда локализованный рендер HearthstoneJSON по `card_id` уже опубликован. Для
диагностики сравнить `X-Card-Image-Source`: значение `placeholder` при наличии
рабочего `/v1/render/latest/ruRU/512x/{card_id}.png` означает ошибку выбора
идентификатора, а не отсутствие исходного изображения.

После патча выполнить контроль полноты обоих catalog snapshot: у каждой записи
должны быть безопасный `card_id` и `images.card`. Для событий патча 36.2 отдельно
проверить, что `JAIL_EVENT_100`, `JAIL_EVENT_101` и `JAIL_EVENT_102` запрашиваются
по каноническим ID, а не по DBF `130085`, `130086` и `130087`.

## Изображения только что вышедших героев

HearthstoneJSON может опубликовать запись героя и full art раньше карточного
рендера `/v1/bgs/latest/ruRU/512x/{card_id}.png`. Такой предполагаемый URL
нельзя сохранять без проверки: `200` у JSON не означает `200` у изображения.

Импортер `sync_hsj_missing_heroes.py` проверяет источники в следующем порядке:

1. локализованный Battlegrounds-рендер HearthstoneJSON;
2. карточка `File:{card_id}.png` на Hearthstone Wiki;
3. full art HearthstoneJSON.

При повторном запуске импортер обновляет только собственные строки с источником
`hearthstonejson.com`, не перезаписывая более полные данные wiki. Общий
`/api/card-image/{card_id}/full.webp` использует тот же порядок резервов и
проверяет `Content-Type: image/*`, чтобы не закэшировать HTML ошибки. Для патча
36.2 контрольные ID — `BG36_HERO_105` и `BG36_HERO_101`; оба изображения и обе
силы героя должны отвечать `200`.

В списке героев клиент должен сначала использовать проверенный same-origin URL
`/api/card-image/{card_id}/full.webp`, если библиотека сопоставила DBF с
`card_id`. Поля `image` из статистического API, wiki и legacy-карты остаются
только резервами для старых героев без библиотечной записи. После релиза нужно
проверить оба контрольных URL в отдельном браузерном контексте и убедиться, что
они декодируются как изображения, а не только отвечают HTTP 200.

## Аксессуары (Trinkets)

Импорт дополнительных библиотек дополняет данные wiki всеми объектами
`BATTLEGROUND_TRINKET` текущего поколения HearthstoneJSON. Конструктор
стратегий и конструктор тир-листов при открытии запрашивают весь активный пул
через `/api/bg/library/extra/trinket?in_pool=1`. Ответ разбивается на малые и
большие аксессуары по `group.slug`, а изображения проходят через
`/api/public-resource/hsjson/` и локальный CDN-кеш.

`public/bg-legacy/accessories-data.js` является только аварийным резервом. Его
устаревание больше не скрывает новые аксессуары, если основной API доступен.

## Контрольный список

- количество новых карт совпадает с примечаниями к патчу;
- русские и английские названия и тексты заполнены;
- изображения отвечают `200`;
- у каждого активного нового существа заполнено `images.golden`, а файл имеет
  ожидаемую геометрию `512x776`;
- новые герои содержат силу героя;
- изображения новых героев не являются заглушками (`X-Card-Image-Source` не
  равен `placeholder`);
- список и таблица героев запрашивают same-origin `/api/card-image/{card_id}`
  раньше внешних URL из статистического ответа;
- каталог и оба конструктора содержат все активные малые и большие аксессуары;
- публичный ответ Arena совпадает с ответом базы;
- `/health/data` не показывает новый источник как устаревший.
