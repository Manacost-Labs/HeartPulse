# Отчёт о красных прогонах и flaky-тестах CI

`npm run ci:flake-report` — метрика эпика «Стабильный CI»: одна команда вместо
ручного разбора логов. Скрипт только читает данные GitHub и ничего не меняет.

```bash
npm run ci:flake-report -- --runs 150                  # таблицы в markdown
npm run ci:flake-report -- --since 2026-10-25T00:00:00Z --json
```

| Флаг | Смысл |
| --- | --- |
| `--runs N` | сколько новейших прогонов `ci.yml` взять (по умолчанию 150) |
| `--since <ISO>` | не брать прогоны, созданные раньше этого момента |
| `--json` | вывод JSON (те же числа, плюс список красных попыток) |
| `--top N` | длина топ-списков (по умолчанию 10) |
| `--repo OWNER/NAME` | репозиторий (по умолчанию — из текущего каталога) |
| `--concurrency N` | параллельных запросов к API (по умолчанию 6) |
| `--no-logs` | не скачивать логи упавших джобов (хуже находит `infra`) |
| `--cache-dir DIR` | каталог кэша (по умолчанию — временный каталог системы) |
| `--no-cache` | не читать и не писать кэш |

Данные берутся через `gh api`: токен из окружения `gh` (`gh auth login` или
`GH_TOKEN`), в коде секретов нет. Без `gh`, без токена или без сети скрипт
печатает понятную ошибку в stderr и завершается с кодом 1 (неверные аргументы —
код 2).

Лимит запросов: токен `gh` даёт 5000 запросов в час и делится со всеми
инструментами и агентами. «Холодный» отчёт на 150 прогонов делает около 2000
запросов (список прогонов, джобы каждой попытки, аннотации тестовых джобов,
логи упавших джобов) и идёт около двух минут. Завершённая попытка не меняется,
поэтому её данные кэшируются на диске, и повторный запуск скачивает только
новые прогоны (несколько десятков запросов). Если лимит исчерпан, скрипт
сразу останавливается с понятным сообщением; уже загруженное остаётся в кэше,
и после сброса лимита запуск продолжится с того же места. Ошибки 5xx и сетевые
сбои повторяются до трёх раз. Кэш можно удалить вручную, он только ускоряет.

## Что в отчёте

- **Прогоны по событиям** (`pull_request`, `merge_group`, `push`). «Красный» —
  итоговая попытка закончилась `failure`/`timed_out`; отдельным столбцом идут
  отменённые и сумма «красные+отменённые» (именно её доля в описании эпика #243
  равна 16,7%). «Позеленели после повтора» — итог зелёный, но более ранняя
  попытка красная; доля считается от всех завершённых прогонов.
- **Классификация красных попыток** (каждая красная или отменённая попытка
  каждого прогона, включая ранние попытки позеленевших):
  - `cancelled` — отмена (их вытесняет concurrency или человек);
  - `infra` — причина в окружении, и так у каждой упавшей джобы: таймаут джобы,
    потеря раннера, падение шагов setup/checkout/download/`apt-get`, сеть при
    установке зависимостей, не запустившийся Chrome (в аннотациях или в логе
    упавшей джобы; восстановившийся после повтора старт `launchBrowser` не в счёт);
  - `flaky` — тот же код позже прошёл: следующая попытка того же прогона
    зелёная, или другой прогон того же head SHA зелёный, или (merge queue, у
    неё SHA одноразовый) тот же PR позже прошёл очередь без новых коммитов в
    PR между этими прогонами;
  - `real` — остальное: позеленения этого кода не было.
  Порядок проверки: `cancelled`, `infra`, `flaky`, `real`. Свежий красный
  прогон, который ещё не успели перезапустить, попадает в `real`: повторите
  отчёт позже.
- **Длительность** — медиана и p90 (метод ближайшего ранга) по событиям, без
  отменённых прогонов; берётся последняя попытка.
- **Зелёные прогоны с FLAKY** — доля прогонов с хотя бы одним предупреждением
  `FLAKY test` от `scripts/test-suite-runner.mjs` в итоговой попытке. Это
  метрика «ложной» красноты, спрятанной повтором.
- **Топ тест-файлов по FAIL и FLAKY** — по аннотациям `Test failed` и
  `FLAKY test` всех попыток; считаются только блокирующие джобы (карантин
  `Browser quarantine` и агрегат `CI required` не учитываются).
- **Топ упавших джобов** и таблица красных попыток со ссылками на прогоны и
  причиной классификации.

Цели эпика: красных прогонов `ci.yml` меньше 10% и меньше 5% прогонов,
позеленевших только после повтора. Сравнивайте окна одной длины: при малом числе
прогонов проценты скачут.

## Устройство и тесты

Сеть — только функция `gh api` (`createGhApi`); сборщик и классификатор — чистые
функции. Тесты `tests/ci-flake-report.test.mjs` подставляют ответы GitHub API из
`tests/fixtures/ci-flake-report/github-api.json` на границе вызова `gh` и
проверяют отчёт целиком. Имена джобов и шагов `ci.yml` (`CI required`,
`quarantine`, `Run registered …`) зашиты константами в начале скрипта: при
переименовании обновите их и фикстуру.
