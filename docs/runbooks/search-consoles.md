# Google Search Console и Яндекс Вебмастер

Подтверждение прав на сайт и выгрузки для базы эпика E21 (#367). Продолжение #293.
Входить в аккаунты Google и Яндекса может только владелец; команда доступа к
ним не имеет.

## Где лежат коды

Коды подтверждения хранятся в `config/search-verification.json`: списки
`google[]` и `yandex[]`. Коды публичные (их видно в HTML страницы), это не
секреты. `apps/public-web/app/layout.tsx` выводит каждый код мета-тегом в
`<head>` каждой страницы:

- `google[]` → `<meta name="google-site-verification" content="…">`;
- `yandex[]` → `<meta name="yandex-verification" content="…">`.

Пустой список не выводит ничего. Первый код `google[]` стоит на проде с
2026-09-30; чей это аккаунт, неизвестно, поэтому его не удаляем. Формат кодов
(непустые строки без пробелов и кавычек, без повторов) проверяет
`tests/next-seo-page-metadata.test.mjs`.

Кроме мета-тегов, на проде отдаётся файл подтверждения Яндекса
`public/yandex_eaea2c59052dad81.html` (в репозитории с 2026-07-02). Значит,
сайт когда-то подтверждали в Яндекс Вебмастере файлом; чей это аккаунт, тоже
неизвестно. Файл не удаляем: если владелец найдёт сайт в своём Вебмастере уже
подтверждённым, новый код Яндекса не нужен.

Чтобы добавить код: допишите строку в нужный список, прогоните
`npm run test:next-seo`, откройте PR. После деплоя проверка:

```bash
curl -s https://hearthpulse.net/ | grep -oE '<meta name="(google-site|yandex)-verification"[^>]*>'
```

## Шаги владельца

Сначала посмотреть, нет ли `hearthpulse.net` в списке сайтов своих аккаунтов
Google и Яндекса: тег Google и файл Яндекса уже стоят на проде. Если сайт там
есть и подтверждён, шаг 1 для этого кабинета пропускается.

1. Google Search Console → «Добавить ресурс» → «Ресурс с префиксом URL»
   `https://hearthpulse.net/` → способ «Тег HTML». Яндекс Вебмастер →
   «Добавить сайт» `https://hearthpulse.net` → способ «Мета-тег». Прислать
   лиду оба значения `content="…"`.
2. После деплоя (команда сообщит) нажать «Подтвердить» в обоих кабинетах.
3. В обоих кабинетах в разделе «Файлы Sitemap» добавить
   `https://hearthpulse.net/sitemap.xml`. При желании выдать команде доступ на
   чтение; иначе раз в этап присылать выгрузку по списку ниже.

Не входит сюда: DNS-подтверждение (DNS трогает только владелец) и IndexNow (#304).

## Что выгрузить для базы E21

Раз в этап, после подтверждения прав и когда кабинеты накопят данные:

- **Ошибки обхода.** Google: «Индексирование» → «Страницы», экспорт таблицы
  причин; «Статистика обхода» (Настройки). Яндекс: «Индексирование» →
  «Статистика обхода», «Диагностика сайта».
- **Страницы вне индекса.** Google: «Индексирование» → «Страницы» → «Почему
  страницы не проиндексированы», экспорт в CSV. Яндекс: «Индексирование» →
  «Страницы в поиске» (исключённые, с причинами).
- **Запросы за 28 дней.** Google: «Эффективность» → период «28 дней» → вкладки
  «Запросы» и «Страницы», экспорт. Яндекс: «Запросы и позиции» → период
  28 дней, экспорт.

Файлы владелец присылает лиду; лид кладёт сводку в базу E21 и ссылку на неё
отмечает в #293.
