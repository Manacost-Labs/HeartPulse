# React Doctor: baseline и проверка изменений

## Назначение

React Doctor используется как быстрый регрессионный барьер для нового
frontend-кода. Исторические замечания сохраняются как отдельный техдолг и не
блокируют текущие изменения.

## Baseline

Полный аудит React Doctor 0.5.8 от 24 июля 2026 года с отключённой телеметрией:

- 377 проверенных файлов;
- 773 замечания в 127 файлах;
- 66 ошибок и 707 предупреждений;
- категории: Bugs — 303, Performance — 211, Accessibility — 131,
  Maintainability — 122, Security — 6.

Полный аудит запускается вручную:

```bash
react-doctor . --no-telemetry --blocking none
```

Эти числа не являются CI-порогом. Они нужны для плановой разборки
исторического долга и сравнения будущих полных аудитов.

## Обязательная проверка

```bash
npm run lint:react-changed
```

Команда:

- запускается только когда изменён авторский JavaScript/TypeScript в `src`;
- не считает изменение `src/vendor` причиной для запуска;
- анализирует проект целиком в `changed`-режиме, чтобы не потерять React
  контекст и связанные новые findings из того же diff;
- сравнивает локальные изменения с `origin/main`, pull request — с
  `origin/<base>`, push в CI — с SHA до push (или родительским коммитом, если
  событие не передало предыдущий SHA);
- преобразует выбранную базу в точный SHA до запуска React Doctor;
- всегда передаёт `--no-telemetry`;
- печатает правила, файлы и строки через `--verbose`;
- использует `--scope changed`, поэтому исторические findings не попадают в
  результат;
- завершает CI ошибкой только при новой диагностике уровня `error`; warnings
  остаются видимыми для triage.

Базу можно явно переопределить через `REACT_DOCTOR_BASE=<git-ref>`. Для
безопасной проверки команды без запуска сканера используется
`REACT_DOCTOR_DRY_RUN=1`.

## Triage

Новые findings сначала проверяются вручную:

1. Подтвердить, что строка принадлежит текущему diff.
2. Для спорного правила выполнить `react-doctor rules explain <rule>`.
3. Исправить true positive и повторить changed-проверку.
4. False positive не отключать глобально без отдельного обоснования и теста.
5. Не запускать массовый autofix по историческому baseline.
