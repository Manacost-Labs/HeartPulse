# ADR 010: детерминированный аудит перед эскалацией в Codex

## Статус

Принято.

## Контекст

После патча меняются несколько независимых поставщиков: Blizzard,
HearthstoneJSON, wiki и статистические сервисы. Постоянный запуск LLM для
полного обхода сайтов дорог, недетерминирован и расширяет поверхность
prompt-injection. Автоматическая публикация непроверенного импорта опаснее
краткой задержки данных.

## Решение

Каждый час systemd запускает дешевый планировщик. Он выполняет аудит раз в
шесть часов или каждый час в течение 72 часов после release-сигнала.
Детерминированный слой нормализует ответы в хеши, счетчики и коды инвариантов.
Codex запускается только для ошибки полноты или изменения источника с
`escalateOnChange: true`, получает закрытый evidence envelope и работает в
read-only sandbox.

Pipeline не импортирует и не публикует данные. Исправление и публикация
остаются отдельным, проверяемым workflow.

Существующий upstream-аудит `hs-data-api` остается владельцем проверки сырых
HJSON/wiki и критических feeds. Новый контур независимо проверяет опубликованное
представление Arena и db.kolodahs.ru. Codex не наследует секреты парсеров и
повторно запускается только при изменении сигнатуры проблемы.

## Последствия

- Проверки воспроизводимы без LLM и имеют unit-тесты.
- Патч переводит систему в более частый режим автоматически.
- Внешний текст не становится инструкцией для Codex.
- Для автоматического анализа требуется отдельная авторизация Codex у
  системного пользователя; без нее детерминированный отчет продолжает работать.
- Неуспех заказанного Codex-review дает отдельный код завершения, а неизменная
  проблема не создает повторный review; для review действует retention 90 файлов.
- Новый класс данных требует явного инварианта и обновления манифеста.
