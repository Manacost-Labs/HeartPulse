# ADR-008: Timeweb CDN для публичных изображений

## Статус

Принято и включено в production.

## Дата

4 августа 2026 года.

## Контекст

Пользователи из России сообщали о медленной или нестабильной загрузке изображений. Origin и собственные региональные proxy остаются необходимыми для HTML, API и доступа из разных регионов, однако одинаковые публичные изображения карт выгодно кэшировать ближе к пользователю.

## Решение

Использовать `cdn.arena.hs-manacost.ru` как собственный домен раздачи существующего Timeweb CDN-ресурса. Origin остаётся `arena.hs-manacost.ru`. CDN применяется только к публичным, версионированным изображениям с методами GET/HEAD.

Production использует двухуровневую схему: GeoDNS направляет браузер на европейский, московский или новосибирский edge, региональный edge использует Timeweb CDN как upstream и при его ошибке повторяет запрос с origin. Эта схема сохраняет доступность в РФ и не делает изображение зависимым от одного провайдера.

Переключение выполняется централизованной URL-политикой. Безопасное значение в релизе по умолчанию выключено, а root-managed production-конфигурация включает CDN после DNS, TLS, origin fetch, CORS и cache-hit проверок. Откат возвращает same-origin URL без изменения данных и API.

Cloudflare делегирует дочернюю GeoDNS-зону и не проксирует HTTP-трафик. Региональные edge и Timeweb CDN имеют раздельные диагностические заголовки, поэтому оба уровня кэша остаются наблюдаемыми.

## Рассмотренные варианты

### Оставить только региональные reverse proxy

- Плюс: полный контроль на собственных VPS.
- Минус: мало точек присутствия и больше операционной нагрузки.
- Решение: сохранить proxy для HTML/API и использовать CDN для тяжёлых публичных файлов.

### Использовать технический домен Timeweb в приложении

- Плюс: работает без собственного DNS и сертификата.
- Минус: привязывает публичные URL к провайдеру и усложняет будущую миграцию.
- Решение: технический домен используется только для диагностики; приложение получает собственный домен.

### Проксировать Timeweb CDN через Cloudflare

- Плюс: дополнительный слой кэша.
- Минус: двойной CDN усложняет диагностику, очистку и измерение попаданий в кэш.
- Решение: CNAME оставлен в режиме DNS-only.

## Последствия

- Изображения обслуживаются региональным edge в России или Европе, а промахи проходят через Timeweb CDN.
- HTML, JSON API, авторизация и подписка не переходят на CDN.
- Нужны отдельные проверки доступности custom domain и origin.
- При смене CDN-провайдера достаточно изменить DNS и URL-политику, не меняя публичные пути изображений.

## Проверка

- `dig +short CNAME cdn.arena.hs-manacost.ru`;
- `curl -I https://cdn.arena.hs-manacost.ru/api/card-image/<id>/thumb.webp`;
- повторный запрос показывает cache hit;
- браузерная Network-проверка подтверждает CDN hostname и отсутствие CORS/TLS ошибок.
