# Членство подписчиков Boosty в VIP-канале

В разделе админки Boosty нужна информационная колонка «В Telegram-канале».
Она показывает членство именно в `KolodaHearthstone | VIP`
(`-1002311131780`), а не подписку, доступ к сайту или членство в другом чате.

## Данные и поведение

- Используются существующие административные GET Boosty subscribers и Telegram
  accounts. Они загружаются параллельно через `useAdminResource`.
  «Обновить» перечитывает оба источника. Telegram accounts возвращает сохранённые
  результаты проверки, не запускает новую проверку в Telegram.
- Строка Boosty сопоставляется с аккаунтом HearthPulse по точному email после
  удаления краевых пробелов и приведения к нижнему регистру. Имя, username и
  контактная строка не используются. Неоднозначный email не даёт подтверждения.
- Галочка «В канале» требует свежего успешного результата для этого канала:
  `member`, `administrator`, `creator` либо `restricted` с явным членством.
- «Нет в канале» требует успешного `left`, `kicked` либо `restricted` с явным
  отсутствием членства. Доступ к другим чатам не влияет на эту колонку.
- Отсутствие привязки, ошибка, неизвестный результат и устаревшая проверка
  различаются. Неизвестное не считается отсутствием в канале. Для проверки
  показывается дата; пояснение в таблице называет источник данных.
- Индикатор только для чтения: не меняет членство и не выдаёт права. Новые токены
  или Telegram ID в браузер не передаются; административная авторизация сохранена.

## Реализация и оформление

React 19, TypeScript. Модель статуса — `src/modules/adminCrm`; композиция —
`adminConsole/sections/IntegrationSections.tsx`; таблица — `ContestAdminBoosty.tsx`.
Используются существующие стили статусов и адаптивные строки таблицы.
Галочка сопровождается текстом, статусы различаются не только цветом.
Новых зависимостей и миграций нет.

## Приёмка и проверка

1. Таблица и Storybook различают присутствие, отсутствие, отсутствие привязки,
   ошибку и устаревшую проверку.
2. Тесты проверяют точный канал, ошибки, `restricted`, дубликаты email,
   нормализацию email и независимость от доступа к сайту.
3. Поиск, пагинация и обновление работают. На desktop/mobile нет нового
   переполнения, ошибок консоли или потери доступных подписей.

Команды: `npx tsx tests/admin-integration-lists-model.test.ts`,
`npm run test:admin-boosty-routes`, `npm run test:registry`,
`npm run security:semgrep`, `npm run test:storybook`, `npm run build-storybook`.
Для браузерной проверки — `npm run storybook`.

Изменяются только колонка, её модель, композиция, тесты и документация.
