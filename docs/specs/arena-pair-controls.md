# Спецификация: контрольные колоды для сочетаний Арены

## Цель

Администратор должен отличать сочетание, которое даёт дополнительный эффект,
от двух сильных или просто популярных карт. Расчёт остаётся честно ограничен
последними 500 забегами с 12 победами и не объявляет причинный прирост винрейта.

## Контракт

Для каждой показанной пары сервер:

1. сохраняет текущую оценку индивидуальной силы A без B и B без A;
2. находит в том же классе и патче похожие контрольные колоды без полной пары;
3. сравнивает качество забегов A+B с качеством уникальных контрольных колод;
4. оценивает сходство по остальным картам, мана-кривой, размеру колоды,
   внешней силе остальных карт и близости даты;
5. учитывает число разных дней, игроков и максимальную долю одного игрока;
6. присваивает одну из категорий:
   - `confirmed` — дополнительный эффект подтверждён внутри 12-win выборки;
   - `promising` — эффект положительный, но выборка ещё предварительная;
   - `popular` — карты встречаются вместе чаще ожидаемого, но отдельный эффект
     пары не подтверждён.

Исследуемые карты A и B исключаются из признаков сходства. Так сама пара не
может искусственно сделать контрольную колоду похожей.

## Порог подтверждения

Категория `confirmed` требует одновременно:

- не менее 15 совместных забегов;
- не менее 15 уникальных контрольных забегов;
- не менее 3 разных дней и 5 игроков;
- долю одного игрока не выше 35%;
- среднее сходство контрольных колод не ниже 30%;
- консервативный дополнительный эффект не ниже 0,75 процентного пункта;
- положительную текущую оценку эффекта после поправки на историю.

`promising` требует не менее текущего минимального порога пары, 5 контрольных
забегов, сходство не ниже 20% и консервативный эффект от 0,5 п.п. Остальные
пары с повышенной совместной встречаемостью относятся к `popular`.

## API и совместимость

Существующий `GET /api/admin/arena-synergies` остаётся защищённым
`adminIdGuard`. В `ArenaCombination` добавляются только новые поля; текущие
поля и `schemaVersion: 2` сохраняются, чтобы ранее записанный last-known-good
оставался читаемым. Интерфейс обязан корректно отображать старый снимок без
новых полей как предварительный результат.

## Структура

- чистый подбор контролей: `server/arenaSynergyMatchedControls.ts`;
- композиция расчёта: `server/arenaSynergyAnalysis.ts`;
- общий контракт: `shared/arenaSynergyContract.ts`;
- админ-интерфейс: `src/features/ContestAdminArenaSynergies.tsx`;
- тесты: `tests/arena-synergy-analysis.test.ts` и существующие route/service
  проверки.

Новых зависимостей, базы данных и публичных маршрутов не добавляется.

## Проверка

- `npm run test:arena-synergies`;
- тест, который сначала падает без matched-control полей;
- тесты подтверждённой, перспективной и просто популярной пары;
- проверка концентрации одного игрока и старого снимка без новых полей;
- `npm run verify:release`;
- Storybook для live/loading/error/last-known-good;
- desktop и mobile browser QA: таблица, категории, подсказки, консоль, сеть,
  accessibility и отсутствие горизонтального overflow.

## Границы

- Всегда: валидировать внешний API, сохранять admin-проверку на сервере,
  исключать идентификаторы игроков из ответа и истории.
- Согласовать отдельно: новый источник проигрышных забегов или изменение
  публичного API.
- Никогда: называть эту оценку доказанным причинным приростом побед.

## Критерии готовности

- Две популярные сильные карты без дополнительного эффекта получают
  `popular`.
- Устойчивая пара с положительным эффектом и разнообразной выборкой получает
  `confirmed`.
- Небольшая положительная выборка получает `promising`.
- Старые LKG-снимки продолжают открываться.
- Тесты, сборка, безопасность, реальный браузер и production smoke проходят.
