# Spec: мягкий paywall для «Меты» и «Архетипов»

Каталог `/standard/archetypes/` обслуживается Next.js. Публичный набор и
фильтры доступны гостю, а расширенная статистика загружается только после
проверки подписки или административной роли. Детальные URL обоих семейств
также обслуживает Next.js.

## Objective

Показать гостю реальные данные текущей меты до точки ограничения и
объяснить ценность тарифа «Алмаз» в контексте выбранной страницы.

- «Мета» показывает фильтры, карту и все архетипы общего среза (винрейт,
  популярность, число игр); платные столбцы и узкие срезы закрыты замком.
  Вольный формат — отдельная страница `/standard/meta/wild/`.
- Каталог архетипов остаётся доступным целиком.
- Страница архетипа показывает обложку, основные показатели и открытые
  сборки: код колоды, список карт со ссылками на страницы карт, винрейт, игры
  и дату (решение владельца 2026-11-18, #444).
- Матчапы по классам, муллиган и статистика карт, история и узкие ранги
  доступны только при действующем entitlement `standard`.

Каталог `/standard/archetypes/` подготовлен как отдельная Next.js-страница.
Гость получает публичный каталог через `/api/constructed-archetypes/teaser`;
подписчик и администратор — полный каталог через защищённый API. Начальные
фильтры `format` и `class` передаются из запроса в серверную разметку и
клиентскую гидратацию одинаково. Next.js-страницы
`/standard/archetypes/:format/:archetypeSlug/` получают только публичный teaser
от Express без cookie посетителя. Сервер явно отбирает публичные поля перед
передачей их в HTML; история и аналитика туда не попадают.
Некорректный формат, slug или отсутствующий архетип возвращают настоящий 404.
У архетипа один URL — `/standard/archetypes/:format/:archetypeSlug/` (E9 S3b,
issue 298). Старое семейство `/standard/meta/:format/:archetypeSlug/` (со
слэшем и без него) nginx отвечает одним `301` на тот же slug в `archetypes` с
сохранением query; Next.js страницу старого семейства не отдаёт, а если её всё
же отдали без nginx, её canonical указывает на `archetypes`. После проверки
доступа клиент загружает полные данные из прежнего защищённого API.

Индексация страниц архетипа (E9 S3a, #297) решается для каждой страницы, а не
для маршрута. Предикат `isIndexableArchetype`
(`shared/constructedArchetypeIndexing.ts`) истинен, когда формат — Стандарт,
выборка не меньше `INDEXABLE_ARCHETYPE_MIN_GAMES` (1000) игр, у архетипа есть
хотя бы одна сборка и популярность больше нуля. Его читают и метаданные Next.js,
и JSON-LD (позже — источник sitemap):

- страница семьи `/standard/archetypes/…` с истинным предикатом получает
  `robots` `index, follow, max-image-preview:large, max-snippet:-1,
  max-video-preview:-1`, self-canonical и JSON-LD (`Organization`,
  `BreadcrumbList`, `ItemPage`, `Dataset`);
- архетип Стандарта ниже порога и любой архетип Вольного формата отдают
  `noindex, follow` и не несут JSON-LD; старое семейство `/standard/meta/…`
  redirect, а не страница (см. выше);
- запись `constructed-archetype-detail` в `publicRouteInventory.json` описывает
  маршрут (`index`, `sitemap: true`), а страница сужает её предикатом; запись
  `standard-meta-legacy-detail` — `kind: redirect`, `expectedStatus: 301`,
  `noindex-follow`;
- заголовок `X-Robots-Tag` на страницы архетипов nginx больше не навязывает
  (E9 S3b, #298): ответ `200` для архетипа Стандарта идёт без заголовка, и
  решает meta `robots` страницы (для слабых архетипов — `noindex, follow`).
  Для Вольного формата nginx оставляет `noindex, follow` («два слоя»: Вольный —
  вторая фаза), для любой ошибки `4xx`/`5xx` — `noindex, nofollow`.
  Заголовок, который отправит само приложение, nginx пропускает без изменений.

Что попадает в HTML страницы архетипа: публичный teaser архетипа, публичный
каталог его формата (те же отобранные поля, `builds` каталога всегда пустой) и
открытые сборки, и ничего больше.

Открытые сборки (E21 OL5b, #444). Ответ
`/api/constructed-archetypes/teaser/:format/:slug` строится поле за полем
(`server/publicArchetypeDetail.ts`): общий срез архетипа и все его сборки
(на проде до 200) страницами по 8: `?buildsOffset=N` отдаёт сборки с N-й,
`buildsTotal` — их общее число, `nextOffset` — смещение следующей страницы в
исходном списке (`null` — страниц больше нет). Клиент берёт смещение только
из `nextOffset`, а не из числа прошедших проверку сборок, и не показывает код
дважды. У сборки поля `deckCode`, `games`, `winrate`,
`updatedAt`, `sampleRank`, `samplePeriod` и `cards` — весь основной список
карт из кода (`id`, `name`, `cost`, `count`, `hasPage`, по возрастанию
стоимости). Карты называются как в конструкторе колод: каталог карт формата,
затем словари `cards_ru.json` и полный HearthstoneJSON
(`server/archetypeCardDictionaries.ts`: источники независимы, локальный
файл отвечает всегда, HearthstoneJSON читается один раз и хранится 6 часов,
после ошибки — пауза 5 минут, первый ответ ждут не дольше 1,5 с). `hasPage` истинен
только у карты каталога формата: только у неё есть страница
`/standard/cards/<format>/<id>/`. Сопутствующие карты легендарок (Гарона,
Броксигар, Сильвана…) выводятся текстом без ссылки, а карта, которой нет ни в
одном словаре, — «Неизвестная карта» с её числом копий; список не
обнуляется. Каталог и словари ждут не дольше 2 с. Если каталог завис или
упал, `cards` равен `null`, код и числа сборки остаются. Ответ без списка или
с неизвестной картой кешируется коротко (`max-age=30`), чтобы составы
вернулись вместе с источником. Платные загрузчики (история, анализ,
ранги) этот маршрут не вызывает. Next.js повторно отбирает
поля (`publicArchetypeTeaserData.ts`, сборка с некорректным кодом или картой
выпадает целиком) и отдаёт их клиентскому `ConstructedArchetypes` данными
(`OpenBuilds`: первая страница, всего, где следующая, читатель следующей
страницы). Гость видит ту же страницу, что подписчик, на тех же компонентах:
галерею сборок `ConstructedArchetypeDeckGallery` (плитки, строки, картинки;
составы рисуются из открытого ответа без запроса `/api/deck/resolve`),
«Сравнение сборок» и «Сравнение с другим архетипом» на открытых данных. Карты
ведут на `/standard/cards/<format>/<id>/` формата архетипа, код колоды лежит в
`data-deck-code` кнопки «Копировать код» и копируется ею. «Загрузить ещё»
догружает следующие страницы тем же открытым маршрутом.
Платное — «Матчапы против классов», «Муллиган и влияние карт», «Винрейт по
рангам», «История архетипа» и очный матчап в сравнении — стоит на своих местах
каркасом с замком (`ArchetypePaidFrames`, `PaidLockButton` с
`closed="paywalled-archetype"`); нажатие открывает оффер подписки
(`PaidOfferProvider entitlement="standard"`). Каркас не выдумывает цифр: только
название раздела и строка о том, что в нём. Подписчику платные данные
подставляются в те же места без перемонтирования: пока проверяется доступ и
грузится платный ответ, на месте замков стоят скелетоны разделов (без замков),
плитки сборок остаются теми же узлами (ключ — код колоды). Перемонтирование
только при потере доступа или смене аккаунта. Без сборок в серверном HTML —
прежняя строка «Колоды появятся, когда наберётся выборка» (у архетипа нет
сборок) или «Сборок пока нет.» (сборки отброшены проверкой полей).
Карточка карты открытого списка несёт `rarity` (белый список, не платное поле).

Геометрия гостя и подписчика одна (QA #627). В шапке у плиток «Винрейт»,
«Популярность» и «Игры» гость видит замок на месте строки изменения (изменение
и спарклайн — платная история; в узкой плитке телефона у замка только
иконка), подписчику до прихода истории место этой строки и спарклайна
зарезервировано (`ArchetypeDossierKpis.css`). Платный список сборок ложится на
открытую галерею (`placePaidBuilds`): каждая открытая сборка остаётся на своём
месте и получает платные цифры, сборки, которых на открытой странице не было
(их отбросил allowlist или ISR-копия старше живого ответа), встают после них;
плиток показывается столько же, сколько до ответа, остальные — за «Загрузить
ещё». Каркас с замком высотой со скелетон загрузки того же раздела у
подписчика: «Винрейт по рангам» — тот же заголовок и резерв таблицы 20,8rem,
анализ (матчапы и муллиган) и история — высоты их скелетонов на ширинах, где
меняется их раскладка (`ArchetypePaidFrames.css`); замок очного матчапа
занимает строку «Загружаем матчапы HSGuru…». Смена «замок → скелетон» ничего
не сдвигает, «скелетон → данные» ведёт себя как у подписчика. Проверка:
`tests/next-archetype-subscriber-geometry-browser.test.mjs` (1440 и 390 px:
высота шапки, каркасы против скелетонов, CLS при приходе истории и при
отличающемся платном списке сборок).

Серверный компонент `ArchetypeSeoSummary` печатает под страницей, у всех
архетипов (в том числе `noindex` и Вольного формата), блок без абзацев текста
(#570, правило владельца: внизу страницы только интерфейс, который видит
человек): заголовок «Среди архетипов <формата>», плашки «Место по играм N из
M», «Медиана формата» и «Медиана класса» (винрейт медианы, разница с архетипом
в п. п. зелёным или красным, в `title` «выше/ниже медианы на N п. п.», подпись
«среди N архетипов … от 1 000 игр»; медианы по архетипам каталога с выборкой от
1000 игр, меньше 5 или 3 строк — плашки нет), строку «дата (`<time datetime>`
из `updatedAt`) · период · Источник: HSGuru» со ссылкой, у архетипа меньше 1000
игр одну строку-подсказку «Выборка меньше 1 000 игр: винрейт ненадёжен», блок
ссылок `<nav>` «Другие архетипы <класса>» (до 6, индексируемые первыми,
название и винрейт) и ссылку «Все архетипы <формата>». Числа `featuredBuild` в
блок и в JSON-LD не берутся (они и так есть в публичном teaser), а история,
матчапы, муллиган и статистика карт не попадают ни в HTML, ни в RSC-поток, ни в
JSON-LD; это проверяют sentinel-тесты `tests/next-seo-page-metadata.test.mjs`,
`tests/next-archetype-details-browser.test.mjs` (метки `mulliganImpact` 7.1717,
`keptImpact` 6.2626 и винрейт точки истории) и
`tests/constructed-archetype-routes.test.ts` (ответ Express). Если у двух
архетипов каталога одинаковое русское название, английское имя в скобках стоит
в title и в ссылках на соседей (H1 страницы остаётся прежним). Если каталог не
ответил за бюджет первой отрисовки (0,6 с), плашек и ссылок на соседей нет:
остаются строка даты и источника и ссылка на каталог. Объём текста
индексируемой страницы держат открытые сборки с составами и плашки: порог
`shared/seoIndexThreshold.ts` (150 своих слов или 10 фактов).

Открытый слой меты Стандарта и Вольного (E21 OL5, #443).
`GET /api/standard-meta/public?format=standard|wild` отдаёт гостю весь общий
срез формата: все строки с `slug`, названием, классом, `winrate`,
`popularity` и `games`, а сверху `totalGames`, `updatedAt` и источник.
Фильтры сервер подставляет сам (ранг «Алмаз — Легенда», любой игрок, порог 100
игр, период, с которого открывается страница); параметры запроса, кроме
`format`, не читаются. Проекция `server/standardMetaPublicSlice.ts` копирует
поля по именам; платные столбцы «Ходы», «Длительность» и «Набор» (`turns`,
`durationMinutes`, `climbingSpeed`) приходят `null`, список других периодов не
отправляется. Платными остаются ранги «Легенда», «Топ-5000», «Топ-Легенда» и
остальные, очерёдность хода, порог игр, периоды патчей, `/standard-meta/trends`,
`recommendation` и `preview/*`; `/api/standard-meta/teaser` работает как
раньше. Контракт `parseStandardMetaApiResponse(value, now, openLayer)` для
открытого слоя считает покрытие только по трём открытым метрикам.
Сервер Next читает `/public` без cookie и печатает все строки в первом HTML
(`StandardMetaPageClient`), поэтому гость без JS и поисковый бот видят одну
и ту же таблицу. Фильтры ранга, периода, очерёдности хода и порога игр у
гостя показаны с замком и ведут к предложению подписки; переключается только
формат (Вольный читает тот же маршрут). Платные столбцы в карточке заменены
значком замка той же ширины, чтобы строка не сдвигалась. JSON-LD Dataset
помечен `isAccessibleForFree: false` и `hasPart` с `.paywalled-standard-meta`.
Тест `tests/standard-meta-public-sentinel.check.ts` подставляет уникальные
метки во все платные поля фикстуры и проверяет, что в ответе их нет; он же
проверяет мутацию (проекция «как есть» его краснит).

Гостевой срез `/standard/meta/` и `/standard/meta/wild/` (все архетипы общего
среза своего формата) и публичный каталог `/standard/archetypes/` сервер тоже
читает у Express без cookie (`apps/public-web/lib/publicStandardMetaTeaser.ts`,
`publicArchetypeCatalogTeaser.ts`) и выводит в первом HTML: гость не ждёт
проверки аккаунта и не делает ни одного запроса из браузера. Express
без параметра `period` отвечает своим периодом по умолчанию, а страница
показывает текущий. Все чтения документа укладываются в общий бюджет 0,6 с:
дольше шапка страницы не ждёт. Сервер отбирает публичные поля (в каталоге
`builds` всегда пустой), а при ответе дольше 0,6 с или ошибке страница
загружает срез в браузере, как раньше. Подписчик видит тот же срез
приглушённым (`aria-busy`), пока полный срез не заменит его; призыв к
подписке появляется только после проверки доступа.

У Вольного свой адрес `/standard/meta/wild/`: свои title, H1, description,
canonical и запись в карте сайта (`standard-meta-wild`). Старый
`/standard/meta/?format=wild` Nginx переводит на него одним 301 с сохранением
остальных параметров запроса (`$arena_meta_wild_target` в
`arena-seo-map.conf`); переключатель формата на странице — ссылки на оба
адреса. Описание Dataset в JSON-LD каждой страницы говорит только о своём
формате. Деградация `/api/standard-meta/public`: свежий срез, затем
последний удачный срез этого формата (`Cache-Control: public, max-age=60`),
затем `503` с `Retry-After: 60` и `no-store`.
Ответ `/api/standard-meta/teaser` кроме трёх строк несёт `totalGames` —
сумму `games` по всем строкам среза (его `quality.sampleSize`), необязательное
целое число. Оно нужно гостю, чтобы «Игр в выборке» в сводке и описании
страницы были числом игр среза, а не суммой трёх показанных строк; строки,
коды колод и прочие платные данные поле не раскрывает. У подписчика полный
список приходит без `totalGames`, и сводка считает сумму по его строкам, то
есть то же число. Парсер `shared/standardMetaContract.ts` пропускает поле как
необязательное неотрицательное целое, а whitelist `publicStandardMetaTeaserData`
получает его оттуда же.
Публичный Nginx направляет страницы деталей в Next.js после проверки
выпущенного релиза.

Каталог источника обоих форматов использует общий серверный кеш
`server/modules/constructedArchetypes`. После истечения срока свежести
разрешённый снимок возвращается сразу, а единственное обновление формата
идёт в фоне. Ошибка не заменяет рабочие данные и не продлевает их максимальный
возраст; `updatedAt` сохраняет время источника. Холодное чтение ограничено
20 секундами. Сброс parser-кеша исключает публикацию запоздалого ответа.
Публичная проекция и защищённый полный ответ применяются после чтения кеша:
аналитика и история по-прежнему не попадают гостю или в серверный HTML.
Сроки, проверка свежести и диагностика описаны в
[инструкции по производительности](../runbooks/constructed-archetypes-performance.md).

## Tech Stack

React, TypeScript, Express, существующие HSGuru datasets и CSS-тема Manacost Arena.

## Commands

- Typecheck: `npm run lint`
- Route tests: `npm run test:standard-meta-routes && npm run test:constructed-archetype-routes`
- UI contract: `npx tsx tests/soft-paywall-ui-contract.test.ts`
- Browser QA: `node tests/soft-paywall-browser.test.mjs`
- Build: `npm run build`
- Security: `npm run security:semgrep`

## Project Structure

- `server/*Routes.ts` — приватные и публичные teaser API-контракты.
- `src/components/PaywallGate.tsx` — общий контекстный CTA.
- `src/features/StandardMeta.tsx` — реальный teaser меты.
- `src/features/ConstructedArchetypes.tsx` — открытый каталог и teaser детали.
- `tests/` — API, source-contract и browser-проверки.

## Code Style

```tsx
{hasFullAccess ? <FullAnalysis /> : (
  <PaywallGate
    active
    presentation="inline"
    surface="archetype"
    title="Колоды, матчапы и муллиган"
  />
)}
```

Используем существующие классы и данные, не создаём отдельную дизайн-систему
и не дублируем проверку подписки на клиенте как security boundary.

## Testing Strategy

- API-тест доказывает, что teaser доступен без подписки и не содержит
  платных полей.
- API-тест доказывает, что teaser отдаёт `totalGames` по всем строкам среза,
  а не по трём показанным, и других новых полей в ответе нет; браузерный тест
  первой отрисовки проверяет то же число в сводке гостя до и после гидратации.
- API-тест доказывает, что полный ответ по-прежнему требует entitlement.
- UI-contract фиксирует маршрутизацию teaser/full endpoint’ов.
- Browser QA проверяет desktop/mobile, overflow, focus targets, console
  и axe.

## Boundaries

- Always: сохранять серверный `accessGuard` на полном payload; исключать
  `deckCode`, `history` и `analysis` из teaser.
- Ask first: изменение тарифа, провайдера оплаты или entitlement.
- Never: считать скрытие DOM/CSS защитой платных данных или отправлять
  приватный payload гостю.

## Success Criteria

- Гость видит реальные teaser-данные вместо размытой заглушки.
- Полные endpoint’ы возвращают 403 без entitlement.
- Teaser-ответы не содержат историю, матчапы, муллиган и статистику карт;
  коды колод есть только у открытых сборок деталей, в каталоге их нет.
- В маршруте Next.js `standard/meta` полный запрос выполняется только после
  проверки подписки; при смене аккаунта или отказе API 401/403 полный набор
  статистики сразу удаляется из отображаемого состояния.
- Подтверждённый администратор видит полную мету и без entitlement `standard`,
  как разрешает защищённый API Express.
- Публичный HTML `/standard/meta/` обслуживает Next.js; существующий API
  остаётся на Express.
- Paywall соответствует пергаментно-бордовой теме и не создаёт
  горизонтальный overflow на 320–1440 px.

## Независимая загрузка архетипов

Сводный каталог использует публичный `/api/constructed-archetypes/teaser` для
всех посетителей: его видимые поля одинаковы и не требуют проверки подписки.
Серверный seed отвечает первому запросу без дубликата в браузере. При отсутствии
seed браузер загружает сводку даже во время проверки аккаунта. В открытой
странице сохраняются только два публичных формата на 30 секунд. Поиск,
сортировка и класс работают локально. Персональные ответы в этот кеш не входят.

Защищённый `GET /api/constructed-archetypes/:format/:slug` поддерживает
`section=core|history|analysis`. Без параметра и с `section=full` прежний полный
ответ сохранён. `core` возвращает метаданные и сборки, `history: []`,
`analysis: null`, не запуская дополнительные чтения. `history` возвращает
`{ history }`, `analysis` — `{ analysis }` с изображениями карт. Все варианты
проходят прежнюю проверку доступа и получают private/no-store. Некорректный
раздел — 400, отсутствующий архетип — 404, недоступный источник блока — 502.

На странице подписчика три запроса независимы. Публичный заголовок остаётся
видимым, галерея сборок (с первой, самой большой выборки) появляется по
готовности core, история располагается после неё. Раздел `ranks` того же
адреса (тот же доступ, private/no-store) отдаёт винрейт архетипа по пяти
рангам и шести периодам HSGuru; сравнение сборок, heatmap рангов и радар
показываются только подписчикам. Гость видит в шапке значения без изменения
к прошлому срезу и спарклайнов: история — платные данные. Каждый дополнительный
блок имеет собственные загрузку, ошибку и повторную попытку. Ошибка истории
не скрывает сборки или аналитику.

История HSGuru накапливается внутри периода (поле `patch` среза: патч или
дополнение) и с новым периодом начинается заново. Поэтому графики истории
разрывают линию на смене периода и подписывают её пунктиром; винрейт идёт с
полосой 95% интервала Уилсона по играм среза; вместо накопленного числа игр
показан прирост за 24 часа внутри периода (база — ближайший срез не моложе
суток того же периода, или первый срез периода, если ему меньше суток; окно
короче 6 часов и уменьшение счётчика оставляют точку пустой). Таблица «Винрейт
по рангам» — нативная таблица с закреплённой колонкой рангов и прокруткой
периодов внутри блока: цвет расходится от 50% (красный ниже, зелёный выше),
насыщенность растёт с отклонением (полная при ±10 п.) и гасится шириной 95%
интервала, так что клетка с малой выборкой остаётся бледной; карточка при
наведении или фокусе показывает игры, интервал и вывод, стоит рядом с клеткой
и не закрывает её.
Код аналитики загружается отдельно, когда блок готов к показу. Его локальная
граница восстановления сохраняет заголовок и сборки при ошибке загрузки кода.
Запросы отменяются при уходе со страницы; дедлайн 25 секунд включает тело.
Защищённые ответы хранятся только в текущем экземпляре страницы, ключ которого
включает аккаунт и доступ. При смене адреса, аккаунта, потере доступа или
ответе 401/403 старые сборки, история и аналитика скрываются. В HTML и общем
браузерном кеше платных данных нет.

## Замки платных метрик и фильтров

Гость видит тот же интерфейс, что и подписчик: платная метрика или фильтр
остаётся на своём месте замком, а не заменяется упрощённым видом. Общий
модуль — `src/shared/ui/PaidLocks.tsx` (доступен и `src/features`, и
`apps/public-web`):

- `PaidMetricLock` — плашка «По подписке» с иконкой замка вместо значения;
  вариант `cell` для ячейки таблицы, `card` для карточки;
- `PaidFilterLock` — замок кнопки или фильтра панели фильтров с названием и
  значением по умолчанию.

Замок доступен с клавиатуры, имя — «<метрика>: по подписке. Узнать, как открыть».
Нажатие открывает оффер ближайшего `PaidOfferProvider`
(`apps/public-web/ui/PaidOffer.tsx`; контекст и хук `usePaidOffer()` лежат в
`src/shared/ui/paidOfferContext.ts`): тот же контекст и `returnTo`, без
инлайн-`PaywallGate`. Платного значения в серверной разметке нет, замок не
получает его в пропах. Параметр `closed` задаёт класс закрытой части
(`paywalled-*`), на который ссылается JSON-LD страницы.

Импорт из `src/features`: `import { PaidMetricLock } from
'../shared/ui/PaidLocks';`. Из `apps/public-web`: `import { PaidMetricLock }
from '@/src/shared/ui/PaidLocks';`.
