# Агент «Контроль HearthPulse»

## Назначение

Агент проверяет полный путь данных Battlegrounds: источник парсера → API →
публичный ответ HeartPulse. Он не считает ответ исправным только потому, что
HTTP-запрос завершился кодом 200.

## Контракт проверки стратегий

Для `list=strategies` проверяются:

- непустой список и совпадение `count` с фактическим числом строк;
- дата получения (`fetchedAt`/`fetched_at`);
- наличие карт минимум в половине стратегий (и минимум в трёх строках);
- для HSReplay — запрет снимка, где все стратегии находятся в D и при этом
  отсутствуют статистические поля.

Последнее правило защищает от текущей регрессии, при которой валидный JSON
показывает 19 стратегий, но все они визуально оказываются в D. Такой результат
получает статус `invalid` и не может быть принят агентом как успешный.

## Режим исправления

Агент сначала запускает аудит, затем диагностирует источник в API парсера.
Исправления выполняются в изолированной ветке соответствующего репозитория,
проходят целевые и полные проверки, после чего публикуются штатным способом с
проверкой ответа HeartPulse и автоматическим откатом при неудаче.

Для локальной проверки используется:

```text
npm run agent:audit:data
```

URL можно переопределить переменной `HEARTPULSE_AUDIT_URL`. Секреты и
production-файлы в вывод не попадают.
