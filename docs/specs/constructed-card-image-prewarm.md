# Предзагрузка изображений карт Стандарта и Вольного

## Проблема

Первый запрос к ещё не закэшированной карте ожидал официальный источник
Blizzard и преобразование в WebP. При поиске или смене фильтра браузер мог
одновременно открыть много таких изображений, поэтому незаполненный серверный
кэш создавал заметную задержку.

## Решение

- Ежедневный сервис читает актуальные каталоги `standard.json` и `wild.json`,
  объединяет и дедуплицирует их DBF ID.
- Для каждого DBF ID берётся URL русской карты из официального Blizzard
  Hearthstone API.
- Из одной загрузки сохраняются две локальные WebP-версии: миниатюра 360 px
  для каталога и 512 px для страницы карты. Имена совпадают с теми, которые
  использует `/api/card-image`.
- Манифест хранит официальный URL источника. Повторный запуск пропускает карту,
  если URL не изменился и файл существует; новый URL обновляет только эту карту.
- Изображения и манифест заменяются атомарно. Загрузка ограничена четырьмя
  одновременными запросами, чтобы фоновая задача не мешала API.
- Frontend использует хеш официального URL как версию запроса. После изменения
  изображения браузеры и edge-прокси получают новый cache key.

Wiki full art и премиальные варианты остаются ленивыми. Массово
предзагружаются только обычные карточки для каталога, поиска, фильтров и
основного изображения на detail-page.

## Эксплуатация

Задача запускается `hs-arena-card-image-sync.timer` ежедневно около 04:20 UTC
с случайной задержкой до 20 минут. Ручной запуск:

```bash
sudo systemctl start hs-arena-card-image-sync.service
sudo journalctl -u hs-arena-card-image-sync.service -n 50 --no-pager
```

Итоговый JSON в журнале содержит количество обновлённых, пропущенных,
отсутствующих и неудачных изображений.
