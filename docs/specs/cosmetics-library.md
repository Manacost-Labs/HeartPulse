# Spec: библиотека косметики Hearthstone

## Objective

Добавить в группу «Разное» публичный раздел `/cosmetics` с тремя
самостоятельными каталогами: скины героев, монеты и питомцы. Каталоги и
индексируемые страницы объектов используют актуальные данные
`db.kolodahs.ru`, русские названия из HearthstoneJSON там, где они
существуют, и визуальный язык Manacost Arena.

Актуальный объём источника на момент разработки:

- 726 скинов героев;
- 57 косметических монет;
- 32 варианта питомцев (8 семейств по 4 раскраски).

## Routes

- `/cosmetics` и `/cosmetics/heroes` — галерея скинов героев.
- `/cosmetics/heroes/:cardId` — страница скина.
- `/cosmetics/coins` — связанные с монетами карты и галерея монет.
- `/cosmetics/coins/:cardId` — страница монеты.
- `/cosmetics/pets` — галерея питомцев.
- `/cosmetics/pets/:cardId` — страница варианта питомца.

Маршруты открытые, server-rendered metadata и sitemap должны позволять
индексацию страниц объектов.

## Data contract

Сервер Manacost является единственной точкой данных для браузера:

- получает компактные страницы каталогов из `db.kolodahs.ru`;
- нормализует URL изображений и не раскрывает внутренние пути сервера;
- объединяет английское имя с `ruRU`-именем HearthstoneJSON по `card_id`;
- возвращает только поля карточки в list endpoint, а Gallery, Sounds,
  full art и другие тяжёлые поля — только в detail endpoint;
- кэширует успешные ответы в памяти/Redis и отдаёт `ETag` +
  `stale-while-revalidate`;
- при временной ошибке источника сохраняет последний корректный ответ.

Список скинов не должен загружать звуки, Gallery или full art для всех
726 объектов. Анимация подгружается только после намеренного hover/focus,
статическое изображение остаётся fallback для touch, reduced motion и
ошибки video.

## Hero filters

- Редкость: Базовые, Обычные (`lite`), Полные (`full`), Алмазные,
  Легендарные, Мифические.
- Класс: все 11 классов Hearthstone.
- Получение: 2500 рунических камней, Боевой пропуск, ивенты и акции,
  недоступные, за деньги/наборы, предзаказ дополнения, достижение
  Tavern Regular, за 1800 золота, за 1200 золота.
- Поиск по русскому/английскому имени, `card_id`, `dbf`.

Фильтры отражаются в query string, работают с клавиатуры и не создают
длинную блокирующую задачу на основном потоке.

## Coins

Перед галереей показываются два компактных раскрываемых блока:

1. «Карты, которые генерируют монеты» — 44 карты.
2. «Карты, которые связаны с монетами» — 3 карты.

Связи одинаковы для всего набора монет и передаются один раз как metadata,
а не дублируются в каждой карточке. В detail показываются `card_id`, `dbf`,
описание и crop/art.

## Pets

Каталог группируется по семейству питомца. Detail показывает карточку,
End Screen, Gallery и блок «Другие раскраски» со всеми вариантами того же
`pet_id`. Переход между вариантами — обычными ссылками, доступными
клавиатуре и поисковым роботам.

## UI and accessibility

- Использовать существующие parchment/wine/gold tokens, рамки, типографику
  и компоненты каталога карт; не создавать новую дизайн-систему.
- Галерея адаптивная: 6 колонок на широком desktop, 2–4 на средних
  экранах, 2 на телефоне.
- Карточка имеет фиксированный aspect-ratio и зарезервированный размер,
  чтобы изображения не создавали CLS.
- Все изображения имеют осмысленный `alt`, видео — доступное имя и
  статический fallback.
- Hover является улучшением, а не единственным способом получить данные.
- Focus ring, target size, контраст и reduced-motion соответствуют WCAG AA.

## Performance budget

- Первый list payload скинов: не более 200 KB compressed.
- Detail загружается отдельным route chunk.
- В initial viewport загружаются только видимые static thumbnails;
  остальные изображения `loading="lazy"`.
- Animated WebM, Gallery, Sounds и End Screen никогда не загружаются на
  стартовой странице каталога без действия пользователя.
- Повторный переход использует ETag/SWR cache и не показывает пустой экран.

## Testing strategy

- Unit tests: нормализация list/detail, русские названия, rarity/category,
  pet family и coin relations.
- Route tests: валидация параметров, компактность list payload, cache
  headers, 404/502/LKG.
- UI contracts: маршруты, фильтры, query state, lazy media, detail blocks.
- Storybook: HeroSkinCard и GalleryFilters, visual states static/hover/error.
- Browser QA: desktop/mobile, hover video, keyboard, reduced motion,
  overflow, console/network и Lighthouse.
- Required gates: lint, focused tests, build, Storybook build, Semgrep,
  React Doctor, Chrome DevTools visual review.

## Boundaries

- Always: показывать происхождение данных и время обновления; использовать
  только allowlisted HTTPS media hosts; санитизировать path/query.
- Ask first: перенос или постоянное зеркалирование внешних Gallery/audio
  файлов в хранилище Manacost, изменение прав доступа или монетизация.
- Never: вставлять HTML источника, проксировать произвольный URL или
  загружать сотни анимаций/аудио при открытии каталога.

## Success criteria

- Раздел «Косметика» доступен из «Разное» и все шесть типов route
  открываются напрямую и после reload.
- Фильтры дают правильные результаты и сохраняются в URL.
- Русское имя используется при наличии; английское остаётся подписью,
  если перевода нет.
- Hover анимация не ухудшает touch/reduced-motion и не создаёт массовых
  запросов.
- Монеты показывают 44/3 связанные карты один раз.
- Питомец показывает End Screen и все другие раскраски семейства.
- Production deploy проходит через `deploy.lock`, ancestry и smoke checks.

## Known constraint

Официальный Miro MCP в текущей сессии недоступен. Спецификация опирается
на прямое подробное задание пользователя и существующую дизайн-систему
проекта; блокер зафиксирован в MC-35.
