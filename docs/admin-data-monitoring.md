# Мониторинг данных в админ-панели

## Назначение

Карточка «Мониторинг данных» находится в административном разделе управления
парсерами. Она сводит в один экран состояние источников, свежесть последнего
успешного снимка, резервную публикацию и ограниченное описание последней
ошибки. Карточка предназначена для быстрой диагностики; полные настройки,
расписание и история запусков остаются ниже на той же странице.

## Источник данных и доступ

Интерфейс использует существующий `GET /api/admin/parser-control`. Маршрут:

- защищён общей проверкой роли администратора;
- возвращает `Cache-Control: private, no-store`;
- обращается к `api.hs-manacost.ru` только на сервере Arena;
- не передаёт браузеру серверный API-ключ.

Отдельный endpoint для сводки не создаётся. Чистая функция
`buildParserMonitoringSnapshot` преобразует уже нормализованный снимок в
стабильную модель отображения. Это сохраняет одно место истины для статусов и
не добавляет лишний сетевой запрос.

## Состояния

- **Штатно** — источник активен и имеет `healthy`-состояние.
- **Обновляется** — источник сообщает `running`; это не считается ошибкой.
- **С ограничениями** — источник сообщает предупреждение, частичный/устаревший
  снимок либо публикацию `stable_baseline`.
- **Критическая ошибка** — источник сообщает `error`, `hard_failed`,
  `unavailable` или ошибку публикации.
- **Приостановлен** — раздел или сам источник отключён; он учитывается в общем
  количестве, но не поднимает тревогу.

Общее состояние становится критическим при любой критической ошибке и
деградированным при предупреждении или использовании резервной версии.
Произвольные строки ошибок сокращаются до 280 символов, а очевидные значения
Bearer/API key/token скрываются перед отображением.

## Обновление

После открытия страницы выполняется обычная загрузка административного
снимка. Затем только мониторинговый снимок обновляется каждые 60 секунд, пока
вкладка видима. Скрытая вкладка не создаёт фоновые запросы. Кнопка «Обновить
сейчас» выполняет ту же безопасную операцию чтения; предыдущий незавершённый
мониторинговый запрос отменяется.

## Диагностика

1. Проверьте общий статус и число критических источников.
2. В блоке «Требуют внимания» найдите источник, его API-state и последнюю
   успешную дату.
3. Метка «Резервная версия» означает, что посетители продолжают получать
   последний проверенный снимок.
4. Для подробностей откройте соответствующий раздел ниже и проверьте расписание
   и историю ручных запусков.
5. Если сама карточка не обновляется, проверьте ответ
   `/api/admin/parser-control`, административную сессию и доступность
   `api.hs-manacost.ru` с backend-сервера.
