# Дисциплина коммитов

Незакоммиченная работа — это потерянная работа и невозможность откатиться
на шаг назад.

## Шаг 1. Проверь, не пора ли коммитить

Пора, если верно любое: завершён осмысленный шаг; изменено ~5 файлов;
прошло ~15 минут; собираешься начать другую задачу.

## Шаг 2. Быстрый гейт

```bash
npm run lint && npm run lint:architecture
```

Красное не коммитится. Подробности — скилл `verify-gate`.

## Шаг 3. Убедись, что коммит атомарен

Перенос и правка — **разные коммиты**. Сначала перенос без изменения
содержимого, потом изменение. Чистый перенос проверяется так:

```bash
git diff -M --stat    # должны быть только переименования
```

## Шаг 4. Сообщение

Conventional Commits, с указанием фазы в теле:

```
refactor(arena): extract TierList page from DeferredRoutes

Фаза 3, шаг 1/3. DeferredRoutes.tsx: 6417 → 4980 строк.
Поведение не менялось, contract- и E2E-тесты без правок.
```

## Шаг 5. Отчитайся одной строкой

После коммита — одна строка в чат: что закоммичено и как изменилась метрика.
Не пересказывай diff.

## Ветки

Работай в ветке фазы: `refactor/phase-<N>-<краткое-имя>`. Не коммить в `main`.

## Чекпоинты

Если шаг долгий, коммить промежуточное как `chore(wip): <что сделано>` и
сквошь перед PR. Лучше грязная история, чем потерянные два часа.

## Чего не делать

- `git push --force` в общие ветки.
- `git reset --hard` без предварительного коммита или stash.
- `--amend` уже запушенного коммита.
- Коммит с секретами — перед пушем прогоняй `npm run security:gitleaks`.
- Коммиты «на всякий случай» с сообщением `fix`, `update`, `wip` без пояснения.
- Коммит с красным `verify:ci` в конце фазы.
- Оставлять хвосты: `git status` должен быть чистым в конце каждого шага.
