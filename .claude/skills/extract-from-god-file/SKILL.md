# Вынесение слайса из хотспота

Порядок миграции задан планом
[`docs/architecture/modularization-plan.md`](../../../docs/architecture/modularization-plan.md)
(принят 29.07.2026). **Сверься с ним перед началом**: часть слайсов уже
выполнена или в работе, а порядок выбран не случайно.

Целевая раскладка — скилл `arch-boundaries`.

## Шаг 1. Возьми ровно один слайс

Один домен за задачу, до пяти авторских файлов, когда это практично.
Вынимай **полный вертикальный слайс**, а не набор несвязанных хелперов.
Если кусок тянет за собой половину файла — граница выбрана неверно.

## Шаг 2. Заяви Documentation impact и зафиксируй базу

Назови документы, которые изменятся. Затем прогони покрывающие тесты
**до** правки — нужен зелёный базовый прогон, иначе не отличишь свою
поломку от чужой:

```bash
npm run test:<домен>
```

Тестов нет — сначала напиши characterization-тест на текущее поведение и
закоммить его отдельно. Это единственный случай, когда тест пишется до
рефакторинга.

## Шаг 3. Перенеси дословно

Скопируй код в новое место без единой правки. Меняй только импорты и экспорт.
Не переименовывай, не «причёсывай», не исправляй замеченные баги.

Коммить перенос отдельно и проверь, что это действительно перенос:

```bash
git diff -M --stat
```

## Шаг 4. Только потом разделяй

Разнесение по `routes/ model/ api/ hooks/ ui/` (клиент) или
`routes/ service/ repository/ model/ schema/` (сервер) — **следующий** коммит.
Исправление найденного бага — **третий**, с префиксом `fix`.

## Шаг 5. Опусти бюджет

Сократил хотспот — опусти его порог в `scripts/check-module-size-budgets.mjs`
до нового фактического значения тем же коммитом. Порог только вниз.

Старый путь удаляй **только после** того, как вызывающий код и тесты перешли
на новую границу.

## Шаг 6. Докажи эквивалентность

```bash
npm run lint && npm run lint:architecture
npm run test:<домен>
npm run lint:react-changed     # React-изменения
npm run security:semgrep       # TypeScript-изменения
npm run qa:screens             # визуальные изменения
```

Публичные URL, формы ответов и права обязаны остаться совместимыми.
Contract- и E2E-тесты должны пройти **без правок в самих тестах**: если тест
пришлось поменять, ты изменил поведение, а не структуру.

Для browser-facing слайсов — реальная проверка через Chrome DevTools MCP.

## Definition of done

- у слайса один владелец и одна публичная точка входа;
- зависимости идут по `app -> modules -> shared`, внутренности никто не тянет;
- публичные URL, формы ответов и права совместимы;
- чистое поведение протестировано без рендера всего приложения;
- типы, фокусные тесты, прод-сборка и бюджеты зелёные;
- заявленный Documentation impact закрыт;
- бюджеты строк и бандла опущены, если хотспот стал меньше.

## Чего не делать

- Не выносить и не чинить в одном коммите.
- Не менять сигнатуры «заодно, раз уж всё равно трогаю».
- Не поднимать бюджеты ради промежуточного состояния.
- Не оставлять реэкспорт-заглушку навсегда: она мост внутри одной задачи.
