# Границы модулей

Контракт: [`docs/architecture/module-boundaries.md`](../../../docs/architecture/module-boundaries.md),
принят [ADR 002](../../../docs/decisions/002-domain-modules-and-documentation-contract.md).
Этот скилл — навигация по нему, а не замена: при расхождении прав документ.

## Направление зависимостей

```
app  ->  modules  ->  shared
```

Композиция владеет связыванием, доменные модули — поведением продукта,
`shared` содержит только доменно-независимые примитивы платформы.

## Раскладка

```text
src/                          server/
  app/                          app/
    providers/                    createApp.ts
    routing/                      middleware/
    shell/                        registerRoutes.ts
  modules/<домен>/              modules/<домен>/
    routes/                       routes/
    model/                        service/
    api/                          repository/
    hooks/                        model/
    ui/                           schema/
    public.ts                     public.ts
  shared/                       shared/
    api/ config/ lib/ ui/         auth/ cache/ db/ http/ observability/
```

Папки — это ответственности, а не обязательный набор пустых директорий.
Маленькому модулю хватит `model/`, `ui/` и `public.ts`.

## Кто что может импортировать

| Источник | Может импортировать |
|---|---|
| `app` композиция | `public.ts` модуля, `shared` |
| Роут модуля | свои hooks/services, адаптеры, UI и model |
| Hook или service | свою model и явные порты |
| API или repository | свои model/schema и `shared` |
| UI модуля | свою model и `shared/ui` |
| Model | другие файлы той же чистой model |
| `shared` | другие узкие примитивы `shared` |

## Обязательные правила

- Model не импортирует React, Express, DOM-глобали, роутеры и сетевые клиенты.
- View не вызывает сырой `fetch`, БД и SDK провайдеров.
- Роуты транслируют границу и композируют, но не копят бизнес-политику.
- API-клиенты и репозитории валидируют внешние данные до доменной логики.
- Межмодульные вызовы идут только через документированный `public.ts`.
- Циклические импорты и импорты из модуля в `app` запрещены.
- Модуль может зависеть от `shared`; `shared` от продуктового модуля — нет.
- Авторизация остаётся видимой на границе серверного роута или use-case.

## Бюджеты размера

| Ответственность | Цель |
|---|---:|
| Роут-энтри или HTTP-адаптер | < 300 строк |
| Model, API-клиент, repository, service | < 250 строк |
| View-компонент | < 500 строк |
| Композиционный корень | < 500 строк |

Ratchet в `scripts/check-module-size-budgets.mjs` — это потолок миграции,
а не разрешение плодить большие файлы. Новое поведение не должно увеличивать
захваченный ratchet-ом хотспот: сначала вынеси владеющий слайс.

## Чего не делать

- Не заводить `utils`, `common`, `helpers`, `misc` — контракт прямо запрещает.
- Не импортировать внутренний путь чужого модуля вида
  `modules/cards/model/privatePolicy`.
- Не делать общеприложенческий barrel, который тянет все домены разом.
- Не продвигать код в `shared` раньше времени: явное дублирование в двух
  доменах лучше преждевременной общей абстракции.
- Не документировать границу вместо того, чтобы включить её в проверку.
