# Новый бэкенд-модуль

Эталон готового модуля — `server/modules/publicApi/`. Смотри его перед началом.

## Шаг 1. Создай структуру

```
server/modules/<домен>/
  routes.ts       только HTTP: разбор, валидация, коды ответов
  service.ts      бизнес-логика, без express
  repository.ts   доступ к данным, без бизнес-логики
  model.ts        типы и схемы домена
  public.ts       ЕДИНСТВЕННЫЙ публичный вход в модуль
  README.md       назначение / источники данных / инварианты
```

## Шаг 2. Соблюди разделение

- `routes.ts` **не обращается к БД напрямую** — только через `service.ts`.
- `service.ts` **не импортирует `express`** — ни `Request`, ни `Response`.
  Принимает и возвращает доменные типы из `model.ts`.
- `repository.ts` не знает про бизнес-правила — только чтение и запись.
- Другие модули видят **только** то, что экспортировано из `public.ts`.

Инфраструктура (redis, sqlite, кэш, rate limit, крипто, планировщик) берётся
из `server/platform/`, а не создаётся внутри модуля.

## Шаг 3. Зарегистрируй в приложении

Роутер подключается в композиционном корне (`server/app/createApp.ts` после
Фазы 4; до неё — в `server/index.ts`). Регистрация — единственное, что корень
знает о модуле.

## Шаг 4. Напиши contract-тест

Тест в `tests/<домен>-routes.test.ts` фиксирует публичный контракт:
пути, коды статусов, форму ответа, заголовки. Добавь npm-скрипт
`test:<домен>-routes` рядом с остальными.

## Шаг 5. Проверь

```bash
npm run lint && npm run lint:architecture
npm run test:<домен>-routes
npm run test:server-build
```

Затем — скилл `checkpoint-commit`.

## Чего не делать

- Не добавлять файл в корень `server/` — там 126 легаси-файлов, их мы разносим.
- Не импортировать внутренности чужого модуля в обход его `public.ts`.
- Не тащить `express` в `service.ts` ради удобства.
- Не менять существующий публичный контракт заодно — см. скилл
  `api-contract-change`.
