# Новый серверный модуль

Контракт: [`docs/architecture/module-boundaries.md`](../../../docs/architecture/module-boundaries.md).
Эталоны в репозитории: `server/modules/publicApi/`, `server/modules/ecosystem/`.

## Шаг 1. Заяви Documentation impact

До правок назови документы, которые изменятся, или `none` с причиной.
Публичное поведение и контракты данных живут в `docs/specs/`.

## Шаг 2. Создай структуру

```
server/modules/<домен>/
  routes/       валидация HTTP-границы, авторизация, сериализация  < 300 строк
  service/      use-cases и доменная оркестрация, без express      < 250 строк
  repository/   персистентность и доступ к внешним провайдерам     < 250 строк
  model/        чистые доменные типы и политика                    < 250 строк
  schema/       валидация запроса, ответа и внешних данных
  public.ts     регистрация роутов или сервисный контракт для корня
```

## Шаг 3. Соблюди разделение

- `routes/` транслирует границу и композирует; бизнес-политику не копит.
- `service/` не использует express-глобали — ни `Request`, ни `Response`.
- `repository/` не знает бизнес-правил.
- `model/` не импортирует express, сетевые клиенты и роутеры.
- `schema/` валидирует недоверенные данные **до** доменной логики.
- Авторизация остаётся видимой на границе роута или use-case.

Зависимости — БД, часы, кэши, клиенты провайдеров — принимаются **явно**.
Не тянись в process-wide изменяемое состояние, если контракт можно описать
явной зависимостью. Инфраструктура берётся из `server/shared/`
(`auth/ cache/ db/ http/ observability/`), а не создаётся внутри модуля.

## Шаг 4. Зарегистрируй в композиционном корне

Регистрация идёт через `server/app/` (`registerRoutes.ts`, `createApp.ts`).
Корень создаёт инфраструктуру и подаёт зависимости; доменных решений и
запросов к БД он не содержит.

## Шаг 5. Напиши contract-тест

Тест фиксирует публичный контракт: пути, коды статусов, форму ответа,
заголовки, права. Добавь npm-скрипт `test:<домен>-routes` рядом с остальными.

## Шаг 6. Проверь

```bash
npm run lint && npm run lint:architecture
npm run test:<домен>-routes
npm run test:server-build
npm run security:semgrep
```

Затем — скилл `checkpoint-commit`.

## Чего не делать

- Не добавлять файл в корень `server/` — там 126 легаси-файлов, их разносят.
- Не импортировать внутренности чужого модуля в обход его `public.ts`.
- Не тащить `express` в `service/`.
- Не наращивать `server/index.ts`: новое поведение туда не добавляется,
  сначала выносится владеющий слайс.
- Не менять существующий публичный контракт заодно — скилл
  `api-contract-change`.
