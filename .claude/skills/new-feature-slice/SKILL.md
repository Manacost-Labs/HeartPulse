# Новый клиентский модуль

Контракт: [`docs/architecture/module-boundaries.md`](../../../docs/architecture/module-boundaries.md).
Порядок миграции: [`docs/architecture/modularization-plan.md`](../../../docs/architecture/modularization-plan.md).

## Шаг 1. Заяви Documentation impact

До правок назови документы, которые изменятся, или напиши `none` с конкретной
причиной. Это требование `AGENTS.md`, а не формальность.

## Шаг 2. Определи домен

Модуль живёт в `src/modules/<домен>/` и владеет **одной** связной
пользовательской или бизнес-способностью. Существующие домены:

```bash
ls src/modules
```

Не заводи новый домен верхнего уровня, не спросив. Один слайс за задачу.

## Шаг 3. Создай структуру

```
src/modules/<домен>/
  routes/     композиция роута, трансляция параметров      < 300 строк
  model/      чистые типы, валидация, политика             < 250 строк
  api/        запросы, валидация ответов, ключи кэша       < 250 строк
  hooks/      состояние браузера и async-оркестрация
  ui/         рендер типизированных данных, интенты        < 500 строк
  public.ts   МИНИМАЛЬНЫЙ стабильный контракт наружу
```

Папки — ответственности. Маленькому модулю хватит `model/`, `ui/`, `public.ts`.
Стремись к пяти авторским файлам за задачу, когда это практично.

## Шаг 4. Соблюди границы

- `model/` не импортирует React, DOM-глобали, роутер и сетевые клиенты.
- `ui/` не вызывает сырой `fetch` — данные приходят из `hooks/` или `api/`.
- `api/` валидирует внешние данные до того, как их увидит доменная логика.
- Наружу торчит только `public.ts`; чужие модули не лезут во внутренние пути.
- Цвета, шрифты, отступы — из токенов, см. скилл `css-tokens`.

Полная таблица разрешённых импортов — скилл `arch-boundaries`.

## Шаг 5. Story и тест

Storybook — обязательная мастерская для авторского React-UI. Заведи или обнови
колокейт `*.stories.tsx`, когда компонент получает значимое визуальное
состояние. Чистое поведение тестируй без рендера всего приложения.

## Шаг 6. Зарегистрируй роут

Lazy-импорт добавляется в манифест роутов в `src/app/routing/`. Манифест —
только манифест, никакой логики страницы.

## Шаг 7. Проверь

```bash
npm run lint && npm run lint:architecture
npm run lint:react-changed
npm run security:semgrep
npm run test:storybook
```

Для browser-facing изменений обязателен реальный просмотр через Chrome
DevTools MCP: вьюпорты, overflow, ошибки консоли, упавшие запросы,
доступность. Текстового ревью недостаточно.

Затем — скилл `checkpoint-commit`.

## Чего не делать

- Не класть файлы плоско в `src/features/` — это легаси-раскладка, она уходит.
- Не называть файлы префиксами вида `ConstructedCardFoo.tsx`: путь несёт домен.
- Не добавлять поведение в захваченный ratchet-ом хотспот — сначала вынеси слайс.
- Не создавать `utils`/`common`/`helpers`.
- Не тянуть данные напрямую `fetch` в компоненте.
