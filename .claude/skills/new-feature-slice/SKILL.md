# Новый фронтенд-слайс

## Шаг 1. Определи место

Слайс живёт в `src/features/<домен>/<фича>/`, где домен — один из:
`arena`, `battlegrounds`, `constructed`, `editorial`, `admin`.
Если фича не ложится ни в один — остановись и спроси, а не создавай новый домен.

## Шаг 2. Создай структуру

```
src/features/<домен>/<фича>/
  ui/<Фича>Page.tsx         презентация, ≤ 400 строк
  ui/<Фича>Page.module.css  только токены, без !important
  ui/<Фича>Page.stories.tsx
  model/use<Фича>.ts        состояние и производные значения
  api/queries.ts            TanStack Query, useQuery/useMutation
  <фича>.test.ts            рядом с кодом
  index.ts                  единственный публичный экспорт
  README.md                 назначение / источники данных / инварианты
```

`README.md` — 10–20 строк, три раздела: назначение, источники данных,
ограничения и инварианты.

## Шаг 3. Соблюди границы

- Импорт данных — только через `api/queries.ts`, никакого `fetch` в `ui/`.
- Компонент страницы принимает ≤ 4 пропса. Всё остальное — из хуков.
- Наружу торчит только то, что экспортировано в `index.ts`.
- Импортировать можно `entities/*` и `shared/*`; другие слайсы — только через
  их `index.ts`.
- Цвета, шрифты, отступы — из токенов, см. скилл `css-tokens`.

Подробности направления зависимостей — скилл `arch-boundaries`.

## Шаг 4. Зарегистрируй роут

Добавь lazy-импорт в реестр роутов. Реестр — только реестр, никакой логики
страницы.

## Шаг 5. Проверь

```bash
npm run lint && npm run lint:architecture
npx tsx --test <путь к тесту>
```

Затем — скилл `checkpoint-commit`.

## Чего не делать

- Не класть файлы плоско в `src/features/` — это легаси-раскладка, её мы убираем.
- Не называть файлы префиксами вида `ConstructedCardFoo.tsx`; путь уже несёт домен.
- Не добавлять глобальный CSS ради одной страницы.
- Не тянуть данные напрямую `fetch`/`useEffect` — только через query-хуки.
