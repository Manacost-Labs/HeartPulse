# Стили: только токены

## Шаг 1. Возьми значение из токенов

Единственный источник цвета, шрифта, отступа и тени — `src/styles/tokens.css`.

```css
/* можно */
color: var(--color-primary);

/* нельзя */
color: #8d171d;
```

Если нужного токена нет — добавь его в `tokens.css` с осмысленным именем,
а не хардкодь значение на месте.

## Шаг 2. Клади стиль рядом с компонентом

Локальные стили — CSS Module рядом с модулем: `src/modules/<домен>/ui/<Компонент>.module.css`.
Глобальные файлы (`src/index.css`, `src/parchment-theme.css`,
`src/route-parchment.css`, `src/battlegrounds-*.css`) — легаси, они только
сокращаются. Не добавляй туда правила ради одной страницы.

## Шаг 3. Не добавляй !important

Лимит зафиксирован в `scripts/check-css-architecture.mjs`
(`MAX_IMPORTANT_DECLARATIONS`, сейчас 1188) и работает как ratchet: только вниз.

Если кажется, что нужен `!important`:

1. Проверь, не перебивает ли тебя глобальный легаси-файл — правь его, а не свой.
2. Подними специфичность на один класс, а не на `!important`.
3. Если перебивает сторонний пакет — оберни в CSS Module и повысь специфичность
   через `:where()` без роста веса.

## Шаг 4. Проверь визуально

```bash
npm run lint:architecture
npm run qa:screens
```

`qa:screens` обязателен после **любой** визуальной правки. Структурный перенос
файла не должен менять картинку вообще: если после переноса поехала вёрстка —
ты сломал каскад, откатывайся.

## Шаг 5. Опусти порог

Если сократил `!important`, опусти `MAX_IMPORTANT_DECLARATIONS` до нового
фактического значения тем же коммитом.

## Чего не делать

- Не поднимать лимит `!important`, чтобы сборка позеленела.
- Не хардкодить hex, `px`-шрифты и тени вне токенов.
- Не добавлять глобальный CSS ради одной страницы.
- Не смешивать перенос стилей и изменение внешнего вида в одном коммите.
